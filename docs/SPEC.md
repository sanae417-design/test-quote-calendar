# Daily Quotes — 製品仕様（初回リリース確定版）

更新日: 2026-08-15  
対象: 初回一般公開（MVP）。後続機能は「将来」として分離する。

この文書が仕様の正本です。実装・見積はこれに合わせます。

---

## 1. 何をつくるか

**Daily Quotes**（日本語表記: デイリークォーツ）

毎日ひとつの名言と短い解説を出し、心に響いたかどうかを残すアプリ。  
カレンダーは製品名ではなく、**過去の日を振り返るためのビュー**である。

ユーザーが直接「今日の気分は？」と答えなくても、  
**どのタイプの言葉にいいねしたか** から、その日に何を求めていたかが残る。

例: カテゴリ「元気がほしい」の名言にいいねした日 → その日は元気が必要だった日。

---

## 2. 初回リリースで採用する案

| 案 | 初回 | 理由 |
| --- | --- | --- |
| 起動は今日の Daily ビュー | 採用 | 毎日開く画面を最短にする |
| Monthly カレンダーがあり、日付タップで Daily へ | 採用 | 「見た日 / 響いた日」が見える最小の振り返り |
| ローカル事前登録データから、未使用の名言をランダム表示 | 採用 | 使用済みフラグで重複を避ける。サーバー不要 |
| 合わなければ引き直し（別の言葉） | **見送り** | 初回は「今日の1件」に集中する。有料化込みで将来 |
| 3種スタンプで気分を記録 | 見送り | 入力が重く、自己分析の信号が散る |
| いいねした Quote のカード一覧 | **採用** | 響いた言葉をあとから見返せる |
| いいねしたカテゴリ色をカレンダーに付ける | 採用 | 自己分析の種を、最小UIで残せる |
| 見ただけ（いいねなし）は薄い色、いいねは濃い色 | 採用 | 開いた日と響いた日を一目で分けられる |
| 月次の自己分析画面 | 見送り | 色付きカレンダーと Liked 一覧が、その前段になる |
| 端末内記録の保存上限 100件。超過は最古から上書き | 採用 | 上限引き上げは将来の有料化候補 |
| 日次記録に名言本文・解説をコピーして残す | 採用 | マスタ更新後も、その日に出した言葉を表示できる |

結論: **初回の核は「未使用から今日の1件 × いいね × カテゴリ色 × いいね一覧」。引き直しは入れない。記録は本文込みで100件まで。**

---

## 3. 画面構成

画面は3つ。

### 3.1 Daily ビュー（起動画面）

起動時は **端末の今日** を開く。

表示するもの:

- 日付と曜日
- 名言
- 短い解説
- カテゴリ（小さなラベル。色はカレンダーと同じ系統）
- **いいね**（心に響いた）。今日の Daily だけ操作できる
- Monthly ビューへの導線
- 端の **いいね一覧** ボタン（Daily / Monthly の両方）

今日以外の日（カレンダーから来た場合）:

- その日に残った名言・解説・カテゴリ・いいね状態を表示
- いいねボタンは出さない（過去は閲覧のみ）
- 「今日へ戻る」と Monthly への導線
- いいね一覧ボタンは出す

未来の日付は選べない。未記録の過去日を開いた場合は「この日の記録はありません」と出し、名言は後から割り当てない。

### 3.2 Monthly ビュー

- 月のグリッド（日曜始まり）
- 前月 / 次月。次月は「今日を含む月」より先へは進まない
- 日付タップで、その日の Daily ビューへ
- 今日は枠などで識別する
- 凡例: 未記録 / 見た（薄色） / 響いた（濃色）と、カテゴリ色の意味
- 端の **いいね一覧** ボタン

セルの色:

| その日の状態 | カレンダー |
| --- | --- |
| アプリを開いていない | 色なし |
| 名言は出したが、いいねしていない | その名言カテゴリの **薄い色** |
| いいねした | その名言カテゴリの **濃い色** |

### 3.3 Liked ビュー（いいねした Quote 一覧）

Daily / Monthly の端のボタンから開く。

- これまでにいいねした名言を、**カード**で並べる（残っている日次記録の範囲。初回は最大100件）
- 新しいいいねほど上
- カードには名言、カテゴリ、最後にいいねした日を出す
- 同じ名言を複数日いいねした場合は **1枚にまとめる**（日付は直近）
- カードをタップすると、直近にいいねした日の Daily へ（過去日なので閲覧のみ）
- 0件のときは「まだ響いた言葉はありません」
- 戻ると、開く前のビュー（Daily または Monthly）へ

いいねのオン/オフは Liked 上では行わない。外すなら、今日の Daily でいいねを解除する。

---

## 4. 名言の出し方（Daily のルール）

1. その日はじめて開いたとき、**使用済みでない名言**からランダムに1件を出す。
2. 出した名言は、**その時点の本文・解説・カテゴリごと**その日の記録にコピーし、**使用済み**にする。再読み込みやマスタ更新のあとでも、その日の表示はこのコピーを使う。
3. 未使用が0件のときは、使用済みをすべて解除してから（今日の1件は除く）もう一度抽選する。一巡したあとだけ、同じ名言が再び出る。
4. 初回に引き直しは無い。今日の1件が、その日の名言である。
5. いいねは今日だけトグルできる。オンで「心に響いた」、オフで「見ただけ」に戻る。オフにすると Liked からも消える（残っている他の日に同じ名言をいいねしていなければ）。
6. 日付の境界は **端末のローカル日付**。日付が変わったら新しい日として 1 から始める。アプリを開いたまま日付が変わった場合も、今日の Daily に切り替える。

---

## 5. カテゴリ（Quote タイプ）

名言マスタの必須項目。カレンダー色と、あとからの自己分析の軸になる。

初回は **4つ**。

| ID | 表示名 | その言葉が響きやすいとき | カレンダー色の役割 |
| --- | --- | --- | --- |
| cheer | 元気がほしい | 落ち込み、疲れ、元気が出ない | 暖色系 |
| calm | 落ち着きたい | 不安、焦り、頭が騒がしい | 青緑系 |
| forward | 前を向きたい | 挑戦、再起、一歩を出したい | 橙〜琥珀系 |
| accept | 自分を認めたい | 自分を責めている、認められたい | 紫系 |

名言は必ずこのどれか1つを持つ。複数カテゴリは初回では持たない。

表示名や色味は実装時に調整してよい。ID と「4分類」は変えない。

用語: 仕様上の正式名は **カテゴリ**。UI では「タイプ」と書いてよい。データ項目名は `category`。

---

## 6. データ

データは2層。**マスタはアプリ同梱、ユーザー操作は端末内メモリ（localStorage）**。

### 6.1 名言マスタ（同梱。ユーザーは書き換えない）

初回はアプリに含める。サーバーからの自動更新は将来。

```json
{
  "id": "cheer-01",
  "quote": "千里の道も一歩から。",
  "description": "大きな目標も、最初の一歩から始まる。",
  "category": "cheer",
  "source": ""
}
```

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| `id` | 必須 | 安定した識別子。文言を直しても変えない |
| `quote` | 必須 | 名言本文 |
| `description` | 必須 | 短い解説 |
| `category` | 必須 | Quote タイプ。`cheer` / `calm` / `forward` / `accept` |
| `source` | 任意 | 出典。自作なら空または「オリジナル」 |

件数の目安: **24〜40件**（各カテゴリ 6〜10件）。  
著作権上問題ない文言だけを入れる。有名な引用を許諾なく使わない。

形式は JSON を正とする。公開用バンドルへの埋め込みは生成物でもよい。

### 6.2 ユーザー記録（端末内。localStorage）

アカウントなし。いいね・使用済み・その日に出した名言の**中身**は、ここにだけ持つ。  
マスタにいいねや使用済みは付けない（マスタは全員共通、状態は人・端末ごとだから）。

抽選は最新マスタから行う。表示（Daily の過去日、Liked、カレンダー色）は、**その日に保存したコピー**を使う。マスタの追加・削除・文言変更があっても、すでに出した日の言葉は変わらない。

```json
{
  "version": 1,
  "historyLimit": 100,
  "quoteState": {
    "cheer-01": { "used": true },
    "calm-03": { "used": true }
  },
  "days": {
    "2026-08-15": {
      "quoteId": "cheer-01",
      "quote": "千里の道も一歩から。",
      "description": "大きな目標も、最初の一歩から始まる。",
      "category": "cheer",
      "source": "",
      "liked": true
    }
  }
}
```

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| `historyLimit` | 必須 | 日次記録の保存上限。初回は **100**。引き上げは将来の有料化候補 |
| `quoteState[id].used` | 抽選に必須 | **使用済みフラグ**。`true` の名言は、未使用が尽きて一巡するまで出さない。キーなしは未使用 |
| `days[date].quoteId` | 必須 | 出した名言の ID。使用済み判定と、同一名言のまとめに使う |
| `days[date].quote` | 必須 | 出した時点の本文。マスタが消えても、この日はこれを表示する |
| `days[date].description` | 必須 | 出した時点の解説 |
| `days[date].category` | 必須 | 出した時点のカテゴリ。カレンダー色の根拠 |
| `days[date].source` | 任意 | 出した時点の出典 |
| `days[date].liked` | 必須 | いいねしたか。カレンダーの濃淡と Liked 一覧の元データ |

Liked 一覧は、残っている `days` のうち `liked === true` を `quoteId` でまとめ、直近の日付順にする。カードの文言は、その直近日のコピーを使う。**いいね専用の別配列は持たない。**

マスタ全体の複製は端末に置かない。残すのは **実際に出した日のコピーだけ**（最大100日分）である。

### 6.3 マスタが変わったとき

| マスタの変化 | 抽選（これから出す日） | すでに保存した日 |
| --- | --- | --- |
| 文言・解説・カテゴリが変わる | 新しい内容を出す | 保存済みのコピーのまま |
| 名言が削除される | 候補から外す。`used` が残っていても抽選しない | コピーがあるので表示できる |
| 名言が追加される | 未使用として候補に入る | 影響なし |
| `id` が変わる | 新しい ID として扱う | 古い日はコピーで表示。旧 ID の `used` は抽選に使わない |

今日の Daily も、一度保存したあとはコピーを表示する。同じ日の途中でマスタが更新されても、今日の言葉は変わらない。

### 6.4 保存上限 100件（古いものから上書き）

上限の対象は **日次記録 `days`** である。カレンダーと Liked の元データ。本文コピーも含む。

1. 新しい日の記録を足すとき、件数が `historyLimit`（100）を超えるなら、**最も古い日付を削除してから**書く。
2. 消えた日は、カレンダーの色も Liked からも、本文コピーも消える（他の残存日に同じ名言のいいねがなければ）。
3. 消えた日の名言でも、`quoteState.used` は **消さない**。一巡するまで同じ ID は再抽選しない。
4. `quoteState` は ID とフラグだけであり、100件上限の対象外とする。
5. `historyLimit` の値自体を保存しておき、将来（有料）で 100 より大きくできるようにする。

使用済みフラグと100件上限は役割が違う。

| | 使用済み `used` | 日次 `days`（上限100） |
| --- | --- | --- |
| 目的 | まだ出していない名言から抽選する | 見た日・本文・いいね・カレンダーを残す |
| 増えるとき | その日の名言を決めたとき | その日はじめて開いたとき |
| 減る / 上書き | 未使用が0件になり、一巡リセットしたとき | 101件目を書くとき、最古の1日を削除 |
| 初回の上限 | その時点のマスタ件数まで | 100件。超過は最古から上書き |

### 6.5 なぜこの分け方か

| 知りたいこと | 見る場所 |
| --- | --- |
| これから出せる名言の本文・タイプ | 最新マスタ |
| まだ出していないか | `quoteState[id].used`（今のマスタに無い ID は無視） |
| ある日に何が出たか（文言含む） | `days[date]` のコピー（`quote` / `description` / `category`） |
| その日に響いたか | `days[date].liked` |
| カレンダーの色 | `days[date].category` + `liked`（残っている最大100日） |
| いいね一覧 | 残っている日の `liked === true` を集約。文言はコピー |

いいねや使用済みをマスタ側に持つと、端末をまたげない。本文を日次にコピーしておかないと、マスタ削除・改稿のあとで過去日と Liked が空になる。

## 7. 初回に含めないもの

- 引き直し（別の言葉）、変更回数制限
- 保存上限（100件）の引き上げ・有料化
- 3種スタンプ、自由記述の日記
- 検索、カテゴリでの絞り込み（Liked 内も含む）
- 月次自己分析の集計画面
- 名言のネット更新・自動DL
- ログイン、クラウド保存
- シェア、画像保存、PWA、ダークモード
- 未来日の先取り表示
- 過去日のあと乗せ・あといいね
- Liked 上でのいいね解除

---

## 8. 将来機能（仕様の延長として予約）

実装しないが、データ形は壊さない。

1. **引き直し / 回数制限 / 有料化**  
   日次記録に `changeCount` を足せる余地を残す。初回のスキーマには含めない。引き直す場合も未使用から選ぶ。
2. **保存上限の引き上げ（有料化候補）**  
   `historyLimit` を 100 より大きくする。既存の `days`（本文コピー込み）はそのまま使える。
3. **名言データの自動更新**  
   同梱 JSON をリモートで差し替える。`id` は維持する。すでに出した日は日次の本文コピーを表示するので、削除や改稿があっても過去は残る。
4. **月次自己分析**  
   その月の「いいねしたカテゴリ」の件数・割合を出す。  
   薄い色（見ただけ）は参考、濃い色（いいね）を主指標にする。残っている日次（上限内）が対象。
5. **スタンプ**  
   いいねを、より細かいリアクションに拡張する余地を残す。初回の `liked` は「最も強い肯定」として移行できる。

## 9. 非機能（初回）

- 静的サイト。サーバー処理なし
- 主要ブラウザの最新版、スマートフォン幅を優先
- 名言は `textContent` で描画し、HTML は埋め込まない
- 動きは `prefers-reduced-motion` を尊重する
- 日付変更を、起動時とタブ復帰時に見る
- 管理用の更新ツールは公開ディレクトリに置かない

---

## 10. 文言の目安（初回）

実装時に磨いてよい。意味はこのまま。

| 場所 | 文言 |
| --- | --- |
| いいね（オフ） | 心に響いた |
| いいね（オン） | 響いた |
| いいね一覧ボタン | 響いた言葉 |
| Liked が空 | まだ響いた言葉はありません |
| 未記録の日 | この日の記録はありません |
| 凡例・見た | 見た |
| 凡例・いいね | 響いた |

アプリ名は **Daily Quotes**。旧称「今日の名言カレンダー」は使わない。

---

## 11. 初回リリースの完了条件

次が揃ったら初回公開してよい。

- Daily / Monthly / Liked が行き来できる
- 今日の名言が、未使用から選ばれ、保存後は再表示しても変わらない
- 使用済みの名言は、一巡するまで再抽選されない
- 引き直しボタンが無い
- いいねは今日の Daily だけで操作できる
- カレンダーが「未記録 / 薄いカテゴリ色 / 濃いカテゴリ色」になる
- いいねした名言がカード一覧になる
- 日次記録は最大100件。101件目で最古が消える
- 過去日は閲覧のみ
- 名言マスタに `category` があり、24件以上、権利上問題ない
- 端末内に `quoteState.used` と、日次の `quoteId` / `quote` / `description` / `category` / `liked` が残る
- 記録は端末内のみである旨が書いてある
- スマートフォンで一通り操作できる
