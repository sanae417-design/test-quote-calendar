## 1. 現状サマリー

このリポジトリは、**バックエンドなしの静的フロントエンド試作**です。日付表示と名言のランダム表示は動きますが、一般公開向けの製品定義・コンテンツ品質・公開基盤・法務・運用は未整備です。

### 今あるもの

| 領域 | 状態 |
| --- | --- |
| ユーザー画面 | `index.html` + `app.js` + `style.css`。日付・曜日・名言・説明・「名言ボタン」 |
| 名言データ | `quotes.csv`（8件）と、同じ内容を `app.js` に埋め込んだ `CSV_TEXT` |
| 更新ツール | `update.js` / `update.css` はあるが、入口の `update.html` は削除済み |
| 画像 | `img/` の SVG 3点（カレンダー・引用符・区切り線） |
| ドキュメント | `README.md` はリポジトリ名のみ |
| ビルド・テスト・CI | なし（`package.json` なし） |
| ホスティング設定 | なし（GitHub Pages / 独自ドメイン未設定） |
| 認証・サーバー | なし（静的サイト） |

### 仕様と実装のギャップ

- 名称は「今日の名言**カレンダー**」だが、カレンダーUIはなく、日付表示＋ランダム名言のみ。
- 「今日の名言」と読めるが、日付に紐づく1日1件ではなく、起動・ボタンごとに乱数で選んでいる。
- 末尾3件（運動／料理／掃除）は試作文で、一般公開向けの文体・品質が揃っていない。
- `quotes.csv` と `app.js` 埋め込み、`quotes - コピー.csv` が三重管理になっている。
- 日付は起動時に一度だけ描画し、日付変更（深夜跨ぎ）を検知しない。
- 公開用メタ情報（favicon、OGP、説明文、ライセンス、プライバシー）がない。

### いまの品質で足りている点

- 名言の描画は `textContent` のため、CSV由来の XSS は起きにくい。
- フォーカスリング（`:focus-visible`）、`aria-live` など最低限のアクセシビリティがある。
- `file://` でも動くよう CSV を JS に埋め込んでいる（ローカル確認向けとしては妥当）。

## 3. プロダクション品質で欠けているもの

静的サイトなので「ログイン基盤」や「サーバーログ基盤」は必須ではありません。欠けているのは、公開サイトとして最低限そろえるべき品質です。

### セキュリティ

| 項目 | 現状 | 一般リリースでの扱い |
| --- | --- | --- |
| 認証・認可 | なし | 閲覧専用なら不要。管理画面を公開する場合のみ必要 |
| XSS | `textContent` 利用で概ね安全 | プレビューや innerHTML 導入時は再点検 |
| CSRF / セッション | 対象なし | バックエンドを足すまで不要 |
| CSP | なし | 公開時に `Content-Security-Policy` を推奨（Google Fonts を許可） |
| 機密情報 | なし | 問題なし。トークン類も未使用 |
| 管理ツール公開 | `update.js` がリポジトリに残存 | 一般公開ディレクトリに置かない。ローカル専用か別リポジトリへ |
| 依存CDN | Google Fonts | フォント自前配信、または CSP とプライバシー方針の明記 |
| 引用の権利 | 出典なし | **公開前の最重要リスク**。許諾のない名言は使わない |

### 認証

- 一般ユーザー向けログインは、現状の閲覧アプリには不要。
- 将来「管理者がWebから名言を編集」する場合のみ、簡易認証または非公開管理画面が必要。
- それまでは CSV / 埋め込み更新をローカル作業に閉じる方が安全で安い。

### エラーハンドリング

- 名言0件時のメッセージはある。
- CSVパース失敗の詳細、画像読み込み失敗、フォント読み込み失敗、日付不正の扱いはない。
- ユーザー向けの再試行・代替表示（フォールバック名言）がない。
- `update.js` 側は try/catch があるが、入口HTMLが無いため使えない。

### ログ出力

- 本番フロントに詳細ログは不要。`console.error` 程度で足りる。
- 公開後に見るなら、プライバシーに配慮したアクセス解析（任意）か、ホスティングのアクセスログ。
- 個人情報を送るログ基盤は、今の機能範囲では過剰。

### その他の品質ギャップ

- 自動テストなし
- Lint / フォーマットなし
- `prefers-reduced-motion` 未対応
- キーボード操作はボタン中心で足りるが、スキップリンクやランドマークの整理は未実施
- 深夜跨ぎ・タイムゾーン（`new Date()` 依存）未考慮
- コンテンツとコードの同期手順が属人的

## 6. 優先度（Roadmap）

### MVP（最低限リリースに必要なもの）

一般公開の定義を「今日の名言を出し、いいねでき、カレンダーで見た日と響いた日が色で分かること」。詳細は [SPEC.md](SPEC.md)。

1. 仕様確定 — 完了
2. 4カテゴリ・24件以上の権利クリアな名言
3. Daily（保存されるランダム1件、別の言葉、いいね）
4. Monthly（薄色=見た、濃色=響いた、タップで過去 Daily）
5. 記録は localStorage。過去日は閲覧のみ
6. 公開用メタ（favicon、description、OGP）と名称変更
7. プライバシー（記録は端末内のみ）
8. GitHub Pages 等での公開と実機確認

**MVP合計**: 約 **26〜42 時間**

### リリース後でよいもの

- 月次自己分析（いいねしたカテゴリの集計）
- 「別の言葉」の回数制限・有料化

- ダークモード、PWA

**後回し合計（よくやる範囲）**: 約 **18〜35 時間**

## 8. 今すぐやらなくてよい判断

- **ログイン機能**: 閲覧専用なら不要。費用対効果が低い。
- **サーバーサイドログ基盤**: 静的ホストのアクセスログで足りる。
- **React / Vue 化**: Daily と Monthly の2画面なら、素のHTML/CSS/JSのままでよい。
- **データベースサーバー**: 名言が数十〜数百件、記録が端末内なら JSON + localStorage で足りる。
- **3種スタンプ / 月次分析**: いいね × カテゴリ色が、その前段になる。

---

## 9. リスク（公開前に潰すもの）

1. **名言の著作権** — 有名な引用を出典・許諾なしで出すと公開後に問題になる。自作か、明らかに利用可能な文言だけにする。
2. **名称と期待値** — 製品名は Daily Quotes。カレンダーは振り返り用ビューであり、日記アプリや本格メンタル記録ではない。
3. **管理ツールの誤公開** — `update.js` を本番サイトに置くと、利用者に不要なファイルが届く。公開セットから外す。
4. **データ不整合** — `quotes.csv` と `app.js` 埋め込みがずれると、更新したつもりで古い名言が出る。
